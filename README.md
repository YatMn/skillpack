# skillpack

English | [简体中文](README.zh-CN.md)

Project-level skill profile installer for Codex, Claude Code, and Cursor.

`skillpack` is an initializer only. It keeps one flat set of scenario profiles
under `profiles/*.yaml`, then delegates real installation to `npx skills` inside
the target project. It does not vendor skill contents, does not install global
skills, and does not treat `skills-lock.json` as source of truth.

## Governance Model

- SkillPack is the only distribution entry for local project skills.
- Codex plugins should be kept for tool capability only, not for skill
  distribution.
- Profiles are named by use case, not by vendor or skill source.
- Vendor and package names belong only in `source` fields inside a functional
  profile.
- `all` is for audit and test coverage only. Do not use it for real projects.
- `skills-lock.json` is generated by `npx skills`; it is ignored by git and by
  SkillPack install decisions.
- Project skill snapshots live under `.skillpack/` and record install metadata
  only. They do not copy skill contents.

## Quick Start

Install into the current project:

```bash
npx github:YatMn/skillpack init workflow --target codex
npx github:YatMn/skillpack add web-app --target codex
```

Install into a specific project from anywhere:

```bash
skillpack init workflow --target codex --project /path/to/project
skillpack add web-app --target codex --project /path/to/project
skillpack add database --target codex --project /path/to/project
```

`skillpack` refuses to install into this repository by default. Use
`--allow-self-install` only when you explicitly want project skills under the
`skillpack` repo itself.

## Targets

`--target` is required for install commands. Supported values are `codex`,
`claude`, `cursor`, and `all`.

| Target | Project skills directory |
| --- | --- |
| `codex` | `.agents/skills` |
| `claude` | `.claude/skills` |
| `cursor` | `.cursor/skills` |
| `all` | Installs `codex`, `claude`, and `cursor`. |

## Profiles

| Profile | Use case |
| --- | --- |
| `workflow` | Planning, branching, review, CI repair, README, and publish workflows. |
| `web-app` | Frontend, React, Next.js, UI, and browser app testing. |
| `deployment` | Hosted web app deployment, env vars, functions, runtime, and verification. |
| `database` | Supabase, Postgres, and storage. |
| `research` | Web research and knowledge extraction. |
| `writing` | Writing, docs, editing, office files, scripts, meetings, data, and slides. |
| `design` | Visual design, brand assets, themes, artifacts, and generated images. |
| `all` | Audit/test aggregate only. |

Show the expanded install plan:

```bash
skillpack show workflow
skillpack show web-app
skillpack show deployment
```

## Profile Entries

Each `skills` entry must include `source` and `why`. `names` is optional:

```yaml
skills:
  - source: obra/superpowers
    why: Planning, TDD, debugging, review, verification, and branch workflow.
```

Omitting `names` installs all skills from that source by calling:

```bash
npx skills add <source>
```

Use `names` only when the profile should install a subset:

```yaml
skills:
  - source: vercel/vercel-plugin
    why: Build React and Next.js apps with common UI and build tooling.
    names:
      - nextjs
      - react-best-practices
```

## Idempotent Installs

For each target, SkillPack checks:

```text
<project>/<target-skill-dir>/<skill>/SKILL.md
```

Existing skills are skipped. Missing skills are grouped by source and installed
with one `npx skills add` call per source. A run ends with a summary like:

```text
summary: installed 3, skipped 14
```

This check does not depend on `skills-lock.json`.

For entries without `names`, SkillPack delegates the whole source to
`npx skills add <source>`. It cannot pre-skip or verify those entries one skill
at a time because the profile intentionally does not list the skill names.

## Project Skill Snapshots

Save the current project's installed skills:

```bash
skillpack snapshot --target codex
skillpack snapshot --target codex --output /path/to/skills.snapshot.yaml
```

By default this writes:

```text
<project>/.skillpack/skills.snapshot.yaml
```

Restore that snapshot in another project:

```bash
skillpack apply /old/project/.skillpack/skills.snapshot.yaml --target codex --project /new/project
```

`snapshot` scans the target skill directory and resolves each skill's `source`
from the project's `skills-lock.json`. If a source cannot be resolved, the
command fails instead of writing an unrestorable entry.

`apply` reads the snapshot, skips skills already present in the target project,
groups missing skills by `source`, and delegates installation to `npx skills`.
Use `--dry-run` to preview the grouped install actions without changing the
target project.

## Local CLI

```bash
git clone https://github.com/YatMn/skillpack.git
cd skillpack
./install.sh
```

Then from any project:

```bash
skillpack init workflow --target codex
skillpack add web-app --target codex,cursor
```

## Commands

```bash
skillpack list
skillpack show workflow
skillpack init workflow --target codex --project /path/to/project
skillpack add web-app --target codex,cursor --project /path/to/project
skillpack snapshot --target codex --project /path/to/project
skillpack apply /path/to/project/.skillpack/skills.snapshot.yaml --target codex --project /path/to/other-project
skillpack doctor --target codex --project /path/to/project
skillpack coverage
```

`restore` remains available only as a legacy passthrough to `npx skills`.
Prefer rerunning the desired profiles.

## Verification

bash -n install.sh bin/skillpack
./bin/skillpack list
